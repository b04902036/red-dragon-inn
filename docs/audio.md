# Optional tavern audio

The compact Sound menu appears beside Language on every page. Music and turn sounds have independent volume and mute controls, plus a master switch. Preferences persist under `rdi:audio`. Defaults are music 20%, SFX 60%, both enabled. The first ordinary click, tap or typing gesture unlocks playback automatically; no separate Enable sound click is needed. Saved disabled/muted preferences remain respected. Passive events, keyboard shortcuts and Tab navigation do not start playback. Music continues across landing, lobby and game; rerenders and resyncs reuse the same decoded audio buffer. Unmount stops music, closes its audio context, pauses chime and voice, and removes listeners. Rejected autoplay returns to the locked state and retries on the next ordinary gesture. Missing media produces a nonblocking notice; gameplay remains available. Enable sound also remains available for an explicit retry.

Background music uses `BufferedMusic`: it resumes a Web Audio context during the user gesture, fetches the local WAV once, and loops an `AudioBufferSourceNode`. This avoids the seek/wait transition at each `HTMLAudioElement.loop` boundary observed in Chrome. A gain node applies music volume; mute stops the source and unmute creates a new source at the saved loop position, reusing the decoded buffer. Muting during load cancels pending playback; unmount also aborts the fetch and releases the context. Chimes and reaction voice retain reusable HTML audio elements and independent SFX controls. The music bytes are unchanged.

`AudioEngine` is the only media construction/playback boundary. The server projection supplies an `attention` object with player, kind and stable key. Turn identity uses match/turn/phase; responses use window/priority/pass/submission identity; choices use window/operation identity; gambling uses source/priority/pass identity. State version, locale and private-state arrival are excluded. The audio layer consumes each local key once and stores a bounded history in sessionStorage, so reconnect, refresh and resync cannot replay an already observed prompt. Locked or muted prompts are consumed without queuing a later surprise sound. A new phase or priority prompt receives its own key.
