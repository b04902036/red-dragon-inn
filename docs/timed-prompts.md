# Server-owned deadlines and phase-end grace

Step 21B extends the same 30-second system to pending ante/payment, gambling checkpoints, pre-payout settlement, committed Fortitude loss, and Order Drink Sometimes opportunities. These use server-private legal eligibility and existing alarms/replay. See [generic capabilities](rdi1-engine-capabilities.md#timing-and-verification).

Production response decisions last 30 seconds; each eligible phase-end Anytime decision lasts 15 seconds. The fixture browser environment injects 10/5 seconds. Older pure rule fixtures explicitly use zero durations to isolate untimed rules; dedicated timer tests use an injected clock and production durations. No client option changes a deadline.

System response eligibility includes legal Anytime holders even without a matching Sometimes. These use the generic source-response decision deadline; private `hasLegalSometimes` remains false and the Sometimes voice stays silent. Anytime alone does not create an Order Drink Sometimes opportunity or change the 15-second phase-end grace.

The persisted control state stores `timedPrompt` (immutable ID, kind, window ID, priority player, opening time and deadline) and a phase-end continuation. One clock reading is supplied per accepted server transaction. Only the authoritative priority holder receives private `responsePrompt` with `hasLegalSometimes`; legal cards and targets stay private. Public state exposes the current countdown/priority, without eligible-hand lists.

Discard/Draw, Action, Order Drink and Drink finish their special action or complete resolution before opening grace. The original phase remains visible until every living holder of a legal Anytime passes. Players without one are skipped. `PASS_ANYTIME` names the phase-end window; normal turn actions cannot bypass grace. An Anytime play suspends grace through all nested response windows, clears its pass consensus and then recomputes from the active-player origin with fresh identities and deadlines. Elimination remains suspended through pending resolution and this grace, allowing last-chance healing.

`GameRoom` commits game state, accepted history/outbox and the next Durable Object alarm in one storage transaction. Alarms and expired reconnect/command reads use the separate `EXPIRE_PROMPT` system boundary; the WebSocket command schema cannot accept it or reserve a `command_system_` identity. Expiry produces deterministic timeout/pass events, advances version, persists to D1 and broadcasts normal projections. A failed D1 mirror retains the durable outbox and schedules a retry. Early/stale alarms cannot pass a newer prompt. Reconnect and hibernation retain the original deadline.

Replay stores the accepted clock reading alongside ordinary commands and the actual expiry time in system actions. It regenerates and verifies all events without consulting the current wall clock. The browser's countdown is presentation only. Optional prompt IDs and authoritative state/window/priority checks reject stale intents.

The English MP3 at `/audio/voice/en-US/sometimes-response.mp3` is shared by English and Traditional Chinese interfaces. A new local response prompt with a legal Sometimes card consumes a `voice:promptId` key once. Locale changes, rerenders, refresh and reconnect do not replay it. Anytime-only, phase-end and remote prompts do not speak. The voice follows the existing SFX volume/mute controls; missing playback cannot block music or gameplay. See [audio provenance](../public/audio/LICENSES.md).

For visual verification, run `npm run dev:fixture` and create/join a room in two separate browser profiles. Discard/draw: the phase remains Discard/Draw while the phase-end countdown and Pass Anytime are visible. Play Quiet Breather to open a response countdown. Wait for timeout and confirm both screens show the next priority automatically. Pass remaining responses/grace, then play Friendly Shove and respond with Brush It Off: the countdown should restart with a new prompt. Switch language/reconnect during a prompt: the deadline stays fixed and the voice does not repeat. Production uses 30/15 seconds rather than the fixture's 10/5.
